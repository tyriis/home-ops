## Intent

Make bifrostix's root filesystem recreated from a known-good snapshot on every
boot. Everything that survives a reboot must be declared. Config drift stops
being a discipline ("anything hand-written on a NixOS system is a lie") and
becomes structural: hand-written state cannot survive.

This also closes the fleet-consistency gap: root moves from the unnamed btrfs
top-level to a named `@` subvolume, matching the fleet's named-subvolume
convention.

## Design

### Subvolume layout

Create beside the running system (non-destructive), then flip:

| Subvolume                             | Mount point             | Lifetime                                                                                                            |
| ------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `@`                                   | `/`                     | deleted and re-snapshotted from `@base` every boot                                                                  |
| `@base`                               | (not mounted)           | read-only pristine seed of `@`; re-seeded only after a proven-good boot                                             |
| `@persistent`                         | `/persistent`           | persistent; the only allow-list root                                                                                |
| `@docker`                             | `/persistent/docker`    | persistent; becomes Docker `data-root`                                                                              |
| `@journal`                            | `/var/log/journal`      | persistent; journald state and sealed journals (own subvolume — see Persistence)                                    |
| `home`                                | `/home`                 | unchanged                                                                                                           |
| `nix`                                 | `/nix`                  | unchanged; the store must not roll back — generations are state                                                     |
| `tmp`, `var/tmp`                      | (deleted)               | replaced by tmpfs via `boot.tmp.useTmpfs` + a `/var/tmp` tmpfs entry (the option covers `/tmp` only; default false) |
| `srv`, `var/lib/{portables,machines}` | (deleted, cleanup pass) | unused                                                                                                              |

`/boot` (vfat, p1) is unchanged and stays writable-boot.

All subvolumes live directly under FS_TREE. The filesystem is one shared
pool: subvolume isolation is a **lifetime** boundary, not a capacity
boundary — a runaway container can consume the whole filesystem unless
qgroups are enabled later. Not a Phase B goal; stated so nobody re-learns it.

### Mechanism — owned module `nixos/modules/impermanence-btrfs.nix`

One module, reused by every future NixOS host. Per-device configuration:
fs device, root subvolume name, base subvolume name, persist subvolume,
bind list.

**Wipe (`boot.initrd.systemd.services."impermanence-wipe"`)** — a
`Type=oneshot` service with:

- `unitConfig.DefaultDependencies = false`
- `after = [ "initrd-root-device.target" ]`
- `before = [ "sysroot.mount" ]`
- `requiredBy = [ "initrd-root-fs.target" ]`
- `serviceConfig.TimeoutStartSec = 0` — the unit default is 90 s and a fat
  `@` delete can exceed it
- `boot.initrd.systemd.initrdBin = [ pkgs.btrfs-progs pkgs.util-linux ]` —
  `extraBin` only symlinks the binary, not its library closure

One mechanical note worth stating because most readers get it wrong:
`btrfs subvolume snapshot` of a **read-only** `@base` produces a
**writable** `@` — the read-only flag does not propagate through
snapshots.

Ordering is the whole mechanism: the wipe must run **after**
`initrd-root-device.target` (device present) and **before** `sysroot.mount`
— once `@` is mounted, deleting it is `EBUSY`.

The script, in sequence. Each numbered step is a gate: an unmet
expectation aborts to `fail_open` unless the step says otherwise.
Remnants use exactly two names — `@new` and `@old`, literal, no
globs — the same ones the wipe itself creates:

1. Mount the filesystem explicitly at **`-o subvolid=5`** — never
   rely on the default-subvolume fallback.
2. **Recover before anything else.** If `@` is absent: promote `@new`
   to `@` if it exists, else rename `@old` to `@`. Write
   `/run/impermanence/FAILED` with reason `recovered` — the boot is
   stale, say so. If `@` cannot be produced at all, **do not
   fail-open**: there is no root to boot, exiting 0 here only delays
   the emergency shell past a confusing mount error. Exit non-zero;
   the initrd SSH and the console are the response for this state —
   proven by the no-root drill case, not assumed.
3. Kill-switch: `impermanence.disable` on `/proc/cmdline` → log,
   write `/run/impermanence/DISABLED`, exit 0. It skips the **wipe**
   — recovery (step 2) already ran, because a skipped wipe with no
   root is not a boot, it is an emergency shell with extra steps. It
   runs before the sentinel gate, so it **also bypasses the
   fail-closed halt**: an operator who sets it has accepted the
   persist surface as-is.
4. Assert the default subvolume: parse
   `btrfs subvolume get-default`, require `ID 5` exactly — a
   substring match against a path is not a check. A changed default
   means escape lane 2 has been destroyed by someone else — abort
   loudly.
5. Sentinel check, then source mkdir (see Persistence): a lost
   persist surface aborts here, **fail-closed** — an exit 0 on empty
   sentinels boots an empty `/var/lib/nixos`, renumbers every uid,
   breaks ownership of every persisted path, and turns the host into
   a permissions-error machine with no console message.
6. Guard: `@base` exists. (Without this, a delete→snapshot pair
   loses both.)
7. Guard: no nested subvolume inside `@` (`btrfs subvolume list`
   against its id is empty). Nested children make `subvolume delete`
   refuse; on vanilla systems that silently boots a stale `@`
   forever.
8. Clean stale `@new` and `@old` remnants — after recovery, only
   while `@` exists. Cleaning before recovery is how a wipe deletes
   its own recovery path: a power loss after `mv @ @old` leaves the
   remnants as the only copies of the tree.
9. Assert both remnant names are now **gone**. If either survives
   (delete refused, crash between attempts), the step-10 rename
   would nest `@` inside a stale `@old` — the wipe would be dead from
   that boot on. This step only asserts; it runs nothing.
10. Wipe — the only step that runs the renames, each guarded:
    `btrfs subvolume snapshot @base @new` →
    `[ ! -e @old ] && mv @ @old` (`fail_open` if the guard fails) →
    `[ -e @new ] && mv @new @` → `btrfs subvolume delete @old` →
    clear
    `/run/impermanence/*` markers (a wipe completed from `@base` is
    a clean root — an old `FAILED` must not report a clean boot as
    failed) → `sync` → unmount. Create-then-swap: any single step
    failing leaves a recoverable tree, and a re-run converges via
    step 2.

`fail_open` = log to console and `/dev/kmsg` with reason, write
`/run/impermanence/FAILED` (stage-1 `/run` is the tmpfs that survives
`switch_root`, so the marker is visible to the running system and
erased on the next boot by construction), unmount best-effort, exit 0. Boot proceeds on the stale `@`. The fail-open contract is
conditional: it applies **only when a viable `@` exists** (or was
recovered at step 2) **and the persist sentinels passed**. With no
root, or an empty persist surface, exit 0 would be a lie — those
states halt and call: initrd SSH, then console.

**The loud half (`impermanence-check.service`, stage-2, oneshot):** reads
the stage-1 markers. If `/run/impermanence/FAILED` exists:
`log -p err` with the reason, write the textfile
`/var/lib/impsnap/impermanence-status.prom` containing
`node_impermanence_wipe_failed 1` (the vmagent textfile directory),
and exit 1 — so the boot also shows
red in `systemctl --failed` and can never be mistaken for clean. If
`DISABLED`: metric 0, loud log, exit 0. On a clean boot it still writes
the textfile with `node_impermanence_wipe_failed 0` — a metric written
only on failure latches at 1 forever once the textfile exists, and a
latching gauge alerts forever after the recovery. This unit is the alert
source;
the central VictoriaMetrics rule (`node_impermanence_wipe_failed == 1`)
lands with the monitoring-lane wiring task. Until then the failed unit
and the root login message (`motd`, set declaratively) are the
signal.

**Persistence binds:** declared as `fileSystems` entries (one mount
mechanism, not a mix of `fileSystems` + hand-written `.mount` units),
every one with:

- `neededForBoot = true` — without it, binds land at `local-fs.target`,
  i.e. after stage-2 `/etc` activation and racing
  nix-daemon/sshd/journald. That race is the uid-renumbering failure this
  spec names as its own justification.
- explicit `Options = [ "bind" ]` + generated `RequiresMountsFor`
  on `/persistent`.
- **Sentinel check before mkdir** (rev 2's stage-2
  `AssertPathExists` was inert: a `neededForBoot` bind starts before
  stage 2 evaluates anything, and the wipe's own `mkdir -p` would
  make any assert vacuous). The wipe service does create missing
  bind sources at runtime — that is why the sentinel must gate the
  mkdir rather than follow it. From the wipe service's
  `subvolid=5` mount, every bind source is at
  `<mnt>/@persistent/<path>`. The sentinel **list is a per-device
  module input** — a static list would fail a fresh host with an
  empty `@persistent` before it could ever seed itself, and this
  module serves every future NixOS host. For bifrostix the list:
  `@persistent/var/lib/nixos/ids` non-empty, `@persistent/etc/ssh`
  holding a key file, `@persistent/var/lib/systemd` present. A
  missing/empty sentinel means `@persistent` lost its contents:
  **halt the boot** (same state as no-root: write the marker to the
  console, exit non-zero). Failing open here boots an empty
  `/var/lib/nixos`, renumbers every uid, changes the networkd DUID,
  and the reservation misses — unreachable with no console message,
  the worst of both designs.

Two entries are **not** binds:

- `/var/log/journal` is its own subvolume `@journal` with
  `neededForBoot = true`. `systemd-journald` has `DefaultDependencies=no`
  and runs `Before=sysinit.target`; a bind arriving at `local-fs` loses
  that race, journald writes to the volatile runtime journal, and
  `journalctl --verify` then passes on nothing — a green check of an empty
  box.
- `/persistent` itself is a normal subvolume mount with
  `neededForBoot = true` (the binds' parent, so it must precede them).

**No `/etc` binds, and no `/etc/machine-id` bind.** The reason is
ownership, not overlay (rev 2 claimed an overlay shadows such binds —
wrong at this pin: `system.etc.overlay.enable` defaults to `false` and
is marked experimental). The real reasons: etc activation manages
declared `/etc` paths itself and does not expect foreign content under
its mountpoints, and `/etc/machine-id` is read by PID1 before
`local-fs.target`, so a bind would never be the effective id anyway.
Replacements:

- Host keys: persist the _data_ under `/persistent/etc/ssh` (contents
  only, not an `/etc` bind) and declare `services.openssh.hostKeys`
  with entries of shape `{ path, type }`. Assigning the option
  **replaces the default set** (`rsa`, `ed25519`,
  `mldsa44-ed25519` — `sshd.nix:371-387`), so declare the full set we
  want, each `path` pointing at `/persistent/etc/ssh/...`. Seed the
  current default key(s) into `@persistent` during migration. Missing
  keys are generated at the configured paths by
  `sshd-keygen.service` (`sshd.nix:991-995`, driven from
  `hostKeys`) — generation lands in `@persistent` and survives. (Rev
  2 attributed this to the reseed; rev 2.1 to a preStart. Neither:
  it is the keygen unit.) The PR-B eval gate re-proves entry shape
  against the pin.
- `machine-id`: declaratively static via `environment.etc."machine-id"`
  with this host's id committed in the config. Deterministic identity
  needs no persistence at all — the store re-renders it every activation.
  Verify during the flip boot that journald sealing still validates
  against it.

**Re-seed (`impermanence-reseed.service`, oneshot, manual start):**
mirrors the wipe's recovery-first structure:

1. mount `-o subvolid=5`, `sync`.
2. Reconcile **all three names** — `@base`, `@base.new`,
   `@base.old`. If `@base` is absent: promote `@base.new`, else
   `@base.old` (a crash between the two renames left the tree as
   `.old`; promoting it is the convergence), then **delete the other
   remnant if it exists** — promotion without deletion strands a
   remnant that step 3's assertion would reject on every later run.
   If `@base` is present: delete `@base.new` and `@base.old`
   remnants.
3. Assert neither remnant name exists. Without this gate, a
   surviving `@base.old` turns the next `mv @base @base.old` into a
   **nest** (`@base.old/@base`, POSIX rename-into-directory), and
   every later run repeats the cycle.
4. `btrfs subvolume snapshot -r @ @base.new`.
5. `mv @base @base.old` when `@base` exists — guarded:
   `[ ! -e @base.old ]`.
6. `mv @base.new @base`.
7. delete `@base.old`, unmount.

A reseed is an operator command: every unmet guard exits
**non-zero** with a message — no silent fallthrough. Nothing to
promote and no `@base`: exit non-zero. Step 5 renames only under
`[ ! -e @base.old ]`; step 7 deletes `@base.old` only when present.

Delete-last, never delete-first: a power loss at any step leaves a
complete `@base` or a complete `@base.new`/`@base.old`, and step 2's
three-name reconcile converges on re-run. Honest
statement: this snapshots a live filesystem, so `@base` is
**crash-consistent, not point-in-time**. Databases on the root volume
must tolerate that; nothing on the allow-list demands more (docker data
lives on its own subvolume, never reseeded via this path).

### Persist allow-list (everything under `/persistent`, bind-mounted unless

listed as a subvolume mount)

- `/persistent/etc/ssh` (contents) — host keys via
  `services.openssh.hostKeys`. Stable identity across reboots and address
  moves.
- `/var/lib/nixos` — uid/gid identity database. Without it, users and
  service accounts renumber every boot.
- `/var/log/journal` (`@journal` subvolume) — sealed journald state and
  logs; Phase A2's seal needs persistent state, and it must be mounted
  before journald starts (see above).
- `/var/lib/systemd` — systemd-networkd runtime state lives here, for
  lease/link continuity. It is **not** a DUID file: systemd v262 uses
  a DUID of type EN derived from the machine id at runtime
  (`networkd-manager.c:705-706`), and this spec pins the machine id
  via `environment.etc."machine-id"` — the client-id stays stable
  with or without this entry, so the reservation never depended on
  this path. Rev 2's "breaks #11969" claim was wrong. Keep the entry
  for state continuity; the sentinel keeps its teeth from uid
  renumbering.
- `/var/log/audit` — auditd rules write here
  (`hardening.nix:156-166`); audit records are a hardening feature and
  must not evaporate.
- `/etc/doco-cd` (contents under `/persistent`) — the parent spec's
  bootstrap secret for this host. Delivered via
  `environment.etc."doco-cd".source = "/persistent/etc/doco-cd"`
  (a **string**, not a path literal — a path value would be copied
  into the store at build time). A declared `/etc` symlink into
  persisted content, no bind involved.
- `/root/nixos` — the config tree (until the host moves to a real git
  checkout of this repo — a tracked follow-up).
- `/persistent/docker` (via `@docker`) — declared Docker `data-root`.
  Requires `RequiresMountsFor=/persistent/docker` on
  `docker.service`, otherwise dockerd can initialise an empty store under
  the ephemeral root and the bind lands over it at mount time — silent
  split-brain. Boot gate verifies `docker info` reports the declared path.

Docker lane note: on top of the shared-pool caveat above, the lane lands
here; per-container capacity controls (qgroups or driver limits) are a
lane-phase decision, not a Phase B promise.

Anything else on `/` has a guaranteed lifetime of one reboot. That is the
feature.

## Decisions

### Reseed trigger — manual (unchanged)

`systemctl start impermanence-reseed` after each change that booted, ran,
and was accepted. An automatic timer (survive-N-minutes promotion) was
rejected: a config that fails at minute six gets promoted by
minute-five-plus-five. Operator ceremony is the cost; "the base is only
ever a state I approved" is the gain. The reseed unit is expected to run
in the same session that ran the switch.

### Wipe failure — fail-open to stale root, made loud

**Chosen: fail-open.** A failed wipe logs loudly, writes
`/run/impermanence/FAILED`, leaves a failed unit behind, boots the stale
`@`, and alerts through the checker metric. Fail-closed (panic/refuse
boot) was rejected: this host has no monitor and its initrd SSH is
unproven at spec time — "refuse to boot" on a headless box is indistinguishable
from "bricked" until someone physically intervenes. Stale-but-bootable
with a proven alert chain is recoverable at leisure; unreachable is not.

Fail-open has exactly two exceptions, both states where "boot anyway"
is a lie rather than a safety net: **no viable root** (nothing was
recoverable) and **empty persist sentinels** (booting would
self-corrupt: uid renumbering, ownership breakage across every
persisted path, evidence destroyed). A DUID change is **not** on
that harm list — the v262 EN DUID derives from the static machine-id
and is unaffected by an empty `/var/lib/systemd`. Those two states
halt the boot and route to the initrd SSH — a halt with a proven
out-of-band path beats a boot that destroys the evidence.

The decision is conditional and the condition is structural, not
aspirational: fail-open is only acceptable _because_ the marker chain is
proven — the break-and-restore drill below is a migration gate, not a
follow-up. The marker alone is not enough: it must be read by the checker,
surfaced as a failed unit, and alerted on before Phase B closes.

Kill-switch: `impermanence.disable` on the kernel cmdline (editable in
systemd-boot at pick time, or via `boot.kernelParams` for a persistent
skip). Semantics: skip the **wipe only** — recovery still runs, since
a skip that yields no root is an emergency shell, not a boot. Write
`/run/impermanence/DISABLED`, boot whatever root exists, loud log.
It is a supported mode for "I know
something is wrong, boot anyway", not an escape from the allow-list
discipline.

### Rollback lane integrity — explicit mounts, `set-default` forbidden

Old generations boot FS_TREE because it is the default subvolume — the
pre-phase cmdlines carry no `subvol=`. A single
`btrfs subvolume set-default @` by anyone (human or future tooling)
silently changes the meaning of every cmdline that asks for nothing,
and the rollback lane is gone without a sound. Therefore:

- Every mechanism in the module mounts with `-o subvolid=5` explicitly;
  none may rely on the default.
- The wipe service asserts the default is still FS_TREE every boot and
  fail-opens loudly if it is not.
- No code path, script, or doc in this repo calls `set-default` on this
  host. Documented as invariant.
- New entries keep carrying `subvol=@` explicitly on the kernel cmdline;
  we do not "improve" the layout by changing the default.

## Escape lanes (ordered by cost)

1. **PR-A first, before any layout change:** initrd SSH, proven by a
   deliberate reboot drill. Requirements the rev-1 spec assumed were
   already true and are not:
   - NIC driver in the initrd: `e1000e` added to
     `boot.initrd.availableKernelModules` (absent today);
   - `boot.initrd.network.enable = true` + `ip=dhcp` on the kernel
     cmdline: the enable flag pulls stage-1 networkd, the generator,
     and `af_packet` via `mkDefault` (`networkd.nix:4291`), so these
     two lines are the complete stage-1 DHCP setup. Alternative for
     a managed link:
     `boot.initrd.systemd.network.networks.<name>.networkConfig.DHCP
= "yes"` (string value).
   - `boot.initrd.network.ssh.enable = true` (defaults to false),
     and the port defaults to 22 — set
     `boot.initrd.network.ssh.port = 2222` explicitly.
   - non-empty `boot.initrd.network.ssh.hostKeys` — the option
     asserts, and the files are **copied into the initrd at build
     time** (`initrd-ssh.nix:233-235`), so they must exist at eval.
     **Committed keypair** for the initrd, dedicated to this host
     and this purpose. Sops-encryption is rejected here on two
     grounds: a sandboxed derivation cannot read the age key, and
     making it readable would place the age key in the store closure
     — a bigger leak than the one avoided. And build-time
     decryption buys no confidentiality anyway: the initrd lands on
     the unencrypted ESP regardless. So the honest exposure is
     stated, not hidden: the initrd host key is public while
     `/boot` is unencrypted — until Phase C LUKS. Separate from
     stage-2 host keys; rotation independent. A committed private
     key is a deliberate exception to this repo's no-plaintext-
     secrets rule: **owner acceptance is posted on #11792 before
     PR-A merges** — git history outlives any key rotation.
     This is the out-of-band path if a boot ever fails before root mounts,
     and Phase C (LUKS2+TPM2) inherits it as its unlock path.

   **Field notes — migration attempt 1 (2026-11-17, live fire):**

   The fail-closed design held exactly as specified: a wrong sentinel path
   (`var/lib/nixos/ids` — this pin's uid state is
   `uid-map/gid-map/declarative-*/auto-subuid-map`, no `ids/`) halted the
   boot at stage-1 with `@` untouched, no renames, no data loss. Two
   lessons for every future recovery from 2222:

   1. **The initrd needs the ESP's filesystem.** `mount` of the vfat ESP
      from initrd SSH failed — no `vfat` module. Repointing the loader
      default is the first move of any stage-1 recovery, so the baseline
      now ships `boot.initrd.kernelModules = [ "vfat" ]` (docker-lane).
   2. **`systemctl switch-root /sysroot` works, but do not pre-mount
      `/sysroot/run`.** Native switch-root migrates the live `/run` and
      `/dev` into the new root; a tmpfs sitting at the destination blocks
      the move, and the incoming world boots with a runtime directory
      nobody can see — no socket, no sshd, no channel. `mkdir` only.

   Also: identify the new generation by the `nixos-rebuild` "Done. The new
   configuration is …" line — never by `ls -dt /nix/store/*nixos-system*`,
   which mixes in unrelated recently-realised store paths and once made a
   correct config look like a missing fstab entry.

2. **Old generations stay bootable as-is** — with the integrity
   invariants above. Rollback = pick an old entry; it boots the
   pre-Phase-B FS_TREE tree untouched (new subvolumes are siblings, the
   migration never deletes or moves the top-level tree).
3. Physical console (present for the flip and drill reboots).

## Migration sequence (one host, one window, deliberate)

1. **PR-A: initrd SSH.** Add `e1000e`,
   `boot.initrd.network.enable = true` + `ip=dhcp`,
   `ssh.enable = true`, `port = 2222`, committed initrd host keys.
   `nixos-rebuild boot`, reboot with `rd.break` on the kernel
   cmdline to hold stage 1 open, and **prove** the 2222 shell while
   `/` is unmounted. No layout work merges before this drill passes.
   (The **no-root drill case** — a missing root must still reach the
   2222 shell — runs at the break step below, since it needs the `@`
   layout to exist.)
2. Create subvolumes beside the live system from FS_TREE: `@`,
   `@persistent`, `@docker`, `@journal`. Seed `@`:
   `rsync -aHAXSx --numeric-ids` with an **explicit exclude list** —
   `/mnt`, `/nix`, `/home`, `/boot`, `/proc`, `/sys`, `/dev`, `/run`,
   `/tmp`, `/var/tmp`, `/var/lib/docker`, and the sibling subvolumes
   the layout deletes anyway: `/srv`, `/var/lib/portables`,
   `/var/lib/machines`, `/var/log/journal`. Explicit, because
   `/mnt/@` sitting inside a scanned tree recurses on the second
   run, and `-x` does _not_ exclude sibling subvolumes (they share
   the fsid). Omitting the last four would copy today's journal and
   dead dirs _into_ `@`, hide them under the new mounts, and break
   the A2 seal chain at the flip without a signal.
   Seed allow-list contents into `@persistent`, named separately:
   `/etc/ssh` host keys; `/var/lib/nixos` (uid state);
   `/var/lib/systemd` (network state); `/var/log/audit`;
   `/root/nixos` — the config tree, the rebuild source
   (`docker-lane.nix:55-56` runs flake builds from it; seeding "nixos
   dir" ambiguously once read as `/var/lib/nixos` and left the host
   with no rebuild source); `/etc/doco-cd` secret. Seed `@journal` by moving the current
   `/var/log/journal` content into it, preserving the seal chain. Docker has no
   containers yet — the lane was deliberately deferred behind this
   phase, so no runtime data moves.
3. Snapshot `@` → `@base` (read-only).
4. **PR-B:** import `impermanence-btrfs.nix` + a new **hand-owned**
   host-fs module for the layout. `hardware-bifrostix.nix` keeps its
   "do not modify" contract; layout overrides live beside it, not in it.
   Contents per Design: `fileSystems` entries for `/` (`subvol=@`),
   `/persistent`, `/persistent/docker`, `/var/log/journal`, **all
   allow-list binds** (each with `neededForBoot`);
   `boot.tmp.useTmpfs` plus the explicit `/var/tmp` tmpfs entry (the
   option covers `/tmp` only); zram stays as-is; Docker `data-root` +
   `RequiresMountsFor`; wipe + checker + reseed units.
   Gate: eval + `--dry-run` build at the pin.
5. `nixos-rebuild boot` (**not** `switch` — the root-mount flip, the bind
   cascade, and sshd ordering are boot-time concerns).
6. **Boot gate (irreversible-by-choice, reversible-by-lane):** reboot,
   verify:
   - `findmnt /` shows `subvol=@`; `mountpoint -q` passes for
     `/persistent`, `/persistent/docker`, `/var/log/journal`, every
     allow-list bind;
   - `docker info` reports `Docker Root Dir: /persistent/docker`;
   - 0 failed units; sshd / docker / networkd / nftables active;
   - `journalctl --verify` clean **and non-vacuous** — entries exist
     under `/var/log/journal` (the rev-1 trap: a green check of a
     volatile empty journal).
7. **Break-and-restore drill (gate for the fail-open decision):**
   plant `touch /root/ephemeral`; from a live session rename `@base` →
   `@base.off`; reboot. Expected and verified: boot succeeds on stale
   `@`, `/run/impermanence/FAILED` present,
   `systemctl --failed` lists `impermanence-check`, the marker reason is
   in the journal, and `/root/ephemeral` **survives** (proof the wipe
   correctly skipped). Then restore `@base.off` → `@base` and reboot:
   expected: marker absent, no failed units, `/root/ephemeral` **gone**
   (the first wipe whose output was _asserted_, not merely assumed —
   the flip boot already wiped), allow-list paths survive, host-key
   fingerprint unchanged. This one drill is simultaneously the
   fail-open proof, the first asserted wipe proof, and the `@base`
   restore drill.
   Final drill case (proves the no-root response, which the design
   must not assume): from the clean system, rename `@` → `@.off`,
   reboot. Expected: no root, non-zero wipe exit, initrd 2222 shell —
   the state the no-root route lands in. **Return path:** from that
   shell, mount FS_TREE at `-o subvolid=5`, rename `@.off` back to
   `@`, `reboot`. The host comes back clean.
8. Reseed: `systemctl start impermanence-reseed` — the base now equals
   the approved state, read-only.
9. Cleanup pass (later PR): delete `tmp`, `var/tmp`,
   `var/lib/{portables,machines}`, `srv` subvolumes; drop the old
   top-level tree once Phase C no longer needs the old-generation
   rollback lane. Same PR: fix the stale
   `docs/backstage/systems/bifrostix/docs/index.md` (still says 26.05 /
   `f1e5c35` / `.232`).

Planned reboots to close Phase B: five — PR-A drill (1), the flip (2),
the break (3), the restore-and-first-asserted-wipe (4), the no-root
proof (5), plus its documented return boot from the initrd shell.
Each drill is self-recovering by design, and the drill reboots are
what make "self-recovering" a tested claim rather than an assumption.

## Non-goals for this spec

- LUKS2 + TPM2 enrollment (Phase C, next: initrd SSH unlock +
  `systemd-cryptenroll` on this layout).
- `@snapshots` history / snapper-style roll-forward. Single base +
  generation-rollback covers the need; history can land later beside it.
- Host git-checkout (config source) — separate follow-up.
- qgroups / per-container capacity limits — docker-lane phase.
- `/home` impermanence treatment. The pilot runs no interactive login
  work today (root only; the `nils` user from the docker-lane parent
  exists and needs a working home at runtime — revisit with the lane,
  where per-container users land).
- `stateVersion` stays `26.05` — no behavior change is being requested
  from this migration.

## How to verify

- After PR-A: an initrd shell on port 2222, reachable while `/` is not
  yet mounted (proven during the drill reboot), authenticating with the
  dedicated initrd key.
- After step 6: every `findmnt`/`mountpoint` assertion above passes on
  the live boot, not just in the rendered config.
- After the step-7 drill cases: fail-open behaves as specified —
  FAILED marker + failed unit + stale root + marker file survives —
  the restore reboot proves the wipe and persistence in one stroke
  (ephemeral gone, every allow-list path present, host-key
  fingerprint unchanged, `journalctl --verify` clean on a non-empty
  `/var/log/journal`), and the no-root case reaches the initrd 2222
  shell and returns via the documented rename.
- Static invariants: no `set-default` anywhere in the repo's nixos tree
  for this host (grep-gate in PR-B CI alongside the existing
  nix-evaluation check); the wipe service asserts
  `btrfs subvolume get-default` = `ID 5` on every boot where the
  wipe runs (the kill-switch skips it, by design).
- After the no-root drill case: an initrd 2222 shell with the root
  subvolume renamed away — the no-root fail path is proven, not
  assumed.
- `btrfs filesystem usage` recorded before the flip and at the close, to
  catch a leak between `@` and persistent subvolumes early.
